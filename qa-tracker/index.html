How this tracker works

One human or agent can hold one active claim at a time. To mark a task as passed, every checklist item must be complete and the report must include the tested branch/commit/PR plus the app version or build.

  • Use gh-pages for the published page and qa-tracker/state.json for shared state unless you have a separate data branch.
  • Failures should include logs or reproduction notes so backend devs can pick them up without re-triaging from scratch.
  • For a public repo, use the GitHub OAuth button as the normal sign-in path. PAT remains as fallback only.
